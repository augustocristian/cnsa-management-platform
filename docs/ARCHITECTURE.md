# CNL Plataforma — Architecture (contract between modules)

100% static PWA (GitHub Pages), no build, JavaScript ES modules, no frameworks.
**All paths must be RELATIVE** (`./js/app.js`), because Pages serves under `/cnsa-management-platform/`.
UI in Spanish (also English and Italian). Mobile-first.

## Persistence (Google Drive, single scope `drive.file`)
**Individual-use app.** There is **no sign-in and no user identity**: the person only *connects Google Drive* (OAuth authorization, single scope `drive.file`; no `openid`/`email`/`profile`, no `userinfo` call, no name/e-mail/picture is ever shown or stored). Their data is saved in **their own Google Drive** (`cnl` folder) only so that it persists and is available on all of their devices (e.g. computer and phone). Drive is **not** a shared database between users: there is no server, database, sharing, roles or multi-user support, and the app shares data with nobody. Swimmers, groups, etc. are records the person manages, not app users. Disconnecting Drive clears the local cache of that device. Without a connected Drive the app offers a **demo mode** (sample data kept only in the browser under `cnl:demo:*`, never sent to Drive, clearly labelled; see the demo-mode bullet in the module list below).
- **Drive connection** (`js/infrastructure/driveConnection.js`, Google Identity Services token flow, authorization only). Scope: `https://www.googleapis.com/auth/drive.file` and nothing else. It is the only data permission: the app only sees the files it creates itself; it is not sensitive and needs no Google verification. **The Sheets API is not used.** Only the Drive API has to be enabled (and the Calendar API if calendar sync is used; its scope `calendar.events` is incremental and is not part of `SCOPES`).
- **Client ID**: constant `BUILTIN_CLIENT_ID` in `js/config.js` (the deployment owner sets it once; end users only connect Drive). If it is empty, the shell shows *Configuración necesaria* (tutorial + a field to try an ID, which is kept only in `localStorage['cnl:clientId']`); the demo remains available. It cannot live in Drive: it is needed before connecting.
- **Start flow** (`presentation/shell/boot.js`, `application/sesionService.js`): `resolveStartMode()` -> `'drive'` (there is a previous authorization; it wins over an old demo flag) | `'demo'` (`localStorage['cnl:mode']='demo'`) | `'start'` (start screen: *Conectar Google Drive* / *Probar la demo*; without a Client ID -> *Configuración necesaria*). Drive mode: `preferencias.conectar` + `drive.listClubs()` -> 0 clubs: club wizard (`views/acceso.js` + `application/asistenteClub.js`, empty club); 1 club or the `ultimoClub`: it is opened; several: selector -> shell. Offline, the cache and the mirrored club list of the preferences are used.
- **Club file** `cnl/<ClubName>.json`: `{ version: 1, club: {key: value}, hojas: { Nadadores: [row...], ... } }` (sections and columns from `schema.js`, `sheetdata.dataToDoc/docToData`). Tagged with `appProperties.cnl='club'` so it can be listed (`drive.listClubs`); renamed when the club name changes.
- **Concurrency (another device of the same user)**: the revision is `md5Checksum` (or `modifiedTime`). `store.refresh` (polling ~30 s, tab visible) compares `drive.meta(id).rev` with the last known one and, if it changed and there are no local edits, reloads. `store.sync` (debounce 1.5 s, *Sincronizar* button, `online` event) checks `meta` before writing and, if there are both local and remote changes, performs a **three-way field-level merge** between `base` (last synced version), local and remote (`sheetdata.mergeData`; conflict on the same field: the local value wins). The write overwrites the content (PATCH `uploadType=media`).
- **Local cache** (`localStorage['cnl:club:<id>']`) as a mirror with the `dirty` flag and the `base`: offline queue of pending changes. `store.status` states: `sincronizado|pendiente|error|offline`.
- **Preferences** `cnl/preferencias.json` (`{version, valores, marcas}`; pure `domain/preferencias.js`, `application/preferenciasService.js` with cache `localStorage['cnl:prefs']`, debounce, offline queue and per-key merge by timestamp; single instance in `js/preferencias.js`). Keys: `idioma`, `ultimoClub`, `clubes` (mirror of the list), `tutorial`, `calendario.vista|ventanaDias|alarmaMin`, `calSync.<key>` (Google Calendar sync map). A future file version is not downgraded and unknown keys are not lost. The language is synchronized as soon as Drive is connected (what was chosen before connecting wins by timestamp).
- **Google errors** (`domain/erroresGoogle.js`, `views/acceso.js#errorGoogle`): popup blocked/closed, account that is not a test user, unauthorized origin (the current origin is shown so it can be copied), Drive API disabled (with an enable link), 401 (renews the token once; if it cannot, *La conexión con Drive ha caducado: Reconectar*), 403/404/429 and offline (`e.offline`). Disconnecting Drive **revokes** the tokens and clears caches.
- **Pre-existing `cnl` folder**: with `drive.file` the app does not see a hand-made `cnl` folder; `drive.ensureFolder` looks for its own and, if it does not exist, creates it (a single one, the oldest if there were several). The UI and the tutorial explain this.
- **PDFs** in `cnl/entrenos/` (`drive.ensureFolderPath(['entrenos'])` + `drive.upload`) and `.xlsx` copies in `cnl/` (`store.guardarXlsxEnDrive`). Exporting/importing `.xlsx` (`store.exportXlsx/importXlsx`) remains the spreadsheet backup.

### Data integrity (`store.js`, `drive.js`, `sheetdata.js`, `cache.js`)
- **Concurrency**: `meta`/`read` request Drive's `version` (a monotonic integer). After the PATCH, if the returned version is not read+1, another device wrote in between: the previous revision is fetched (`revisions.list` + `alt=media`), merged with `mergeData` and rewritten (up to 5 rounds). Rotating daily backup `cnl/backups/<club>-YYYYMMDD.json` (last 14, holding the content from before the first write of the day).
- **Per-field merge** (3-way base/local/remote): per-row logical stamps (Lamport clock `n@tab`, no wall clock) in `doc.sync`, tombstones for deletions (GDPR-purge tombstones are permanent), an edit beats a deletion, and orphan cleanup (Cargas/Asistencia/Marcas/EntrenoLineas/Fases... of deleted parents).
- **File**: `version` greater than `DOC_VERSION` => read-only with a notice; unknown sheets, columns and keys are preserved (`extra`). Unreadable JSON or an emptied file ({}/null while local data exists) => recovery screen (local copy / latest backup / open in Drive); nothing is overwritten without a decision. Types are normalised on read/import (club values text only, phone/licence as text, Excel serial dates to ISO).
- **Network**: `gfetch` has a 30 s AbortController, retries with exponential backoff and `Retry-After` (429/5xx), and distinguishes `storageQuotaExceeded` (`cuota-drive`); a single token request in flight with a deadline; a 90 s watchdog in `store.sync`; polling with growing delay after errors.
- **Local cache**: `saveCache` is debounced (200 ms) and flushed when the tab is hidden/closed; localStorage overflows to IndexedDB; if neither fits the status becomes `error` plus a notice. Two tabs merge through the `storage` event (and `navigator.locks` serialises syncing).
- **Disconnect Drive** (`sesionService.cerrarSesion` + `driveConnection.disconnect`): uploads what is pending (with a deadline); if it cannot, a dialog offers download copy / discard / cancel; afterwards it revokes the tokens and always erases `cnl:club:*`, `cnl:drive-auth`, `cnl:prefs`, `cnl:cal-sync:*`, the demo namespace and the legacy `cnl:user`/`cnl:token` (`cache.limpiarDatosLocales`).
- **Backup / restore** (`domain/backup.js`, `application/backupService.js`, `infrastructure/backupCrypto.js`, `infrastructure/backupDrive.js`, `composicion/backup.js`, `views/backup-panel.js`): the complete lossless copy in one file. Format `cnl-backup` v1 = `{format, formatVersion, appVersion, docVersion, createdAt, club:{name,data}, sheets:{all sheets incl. unknown}, extra:{top}, preferences:{user-level only}, counts, checksum}`; the checksum is SHA-256 over the canonical (key-sorted) JSON without the checksum field, computed through an injected hash port. Optional envelope `cnl-backup-encrypted` (PBKDF2-SHA256 + AES-256-GCM; the parameters are authenticated data). Restore semantics: (1) validate (format, version, checksum, shape, limits); (2) automatic safety copy first (Drive `cnl/backups/<club>-restore-*.json`, last 5; demo mode: in memory + download), nothing is touched if it fails; (3) *replace* = `upsertMany` of new/changed rows + `removeMany` of the rest (tombstones, so other devices converge), *merge* = `mergeData(null, current without tombstones, backup)` (current wins on conflicts, nothing removed); unknown sheets/columns/keys go through `store.aplicarExtras`; (4) rows failing `validarFila` and rows with permanent GDPR tombstones (and their children) are skipped and reported; the club name never changes; (5) `store.migrar()` (legacy objectives/catalogue), category recalculation, user preferences; (6) if applying fails the safety copy is applied back. `store.documento()` exposes the club document. Plain daily/import copies from Drive and the "download JSON copy" file are accepted as sources. The service imports `sheetdata.js`/`schema.js` (pure, domain-target legacy files) directly; everything else is injected. GDPR: a backup holds personal data of minors; copies already downloaded are not affected by an erasure (the UI says so); `drive.listarBackups(name, {todos:true})` lets `purgarNadador` delete the Drive daily, pre-import and pre-restore copies.
- **GDPR**: `store.exportNadador(id)`, `store.purgarNadador(id)` (cascade, permanent tombstone, deletes Drive .xlsx copies, backups and old revisions), validation in `upsert` (`domain/validacion.js`), import with preview, prior backup and limits (20 MB / 50,000 rows).

### Test tool: `js/infrastructure/fakeGoogle.js`
In-memory adapter that replaces the connection (`driveConnection`) and `drive` (same interfaces: simulated connection `connect/disconnect/isConnected/token`, `ensureFolder`, `listClubs`, `createClub`, `meta/read/write`, `leerPreferencias/guardarPreferencias`, `upload`, `findFile`...). It is activated **only** with `window.__CNL_TEST__` (injected by Playwright with `addInitScript`, valid on any host) or with `localStorage['cnl:test']='1'` **and** `location.hostname` being localhost/127.0.0.1 (`js/infrastructure/entornoPruebas.js`; the shell imports it dynamically; it is not downloaded in production). It also simulates Drive's `version`, revisions, `cnl/backups`, permanent deletion and hooks (`escribirAntes`, `corromperClub`, `vaciarClub`, `caducarSesion`). Options: `conectado` (alias `sesion`), `demo` (seeds `store.seedDemo` once into a club of the simulated Drive; it is not the product's demo mode), `sinClientId`, `errorConexion` (alias `errorLogin`), `fallos`; there is no user option. It mirrors its state in `localStorage['cnl:test:drive']` to survive reloads and exposes `window.__CNL_FAKE__` (`clubs()`, `prefs()`, `archivos()`, `editarClubExterno`, `conectar()`, `desinstalar()`). It is used by `tests/helpers/app.js`, the unit tests and the Cucumber steps.

In `cnl/<Club>.json` the `club` section is the object of the *Club* row (key/value) and each entity is an array in `hojas`; the exportable Excel uses the same columns.

| Nadadores | id, nombre, apellidos, fechaNacimiento, sexo, categoria (current, calculated), grupoId, email, telefono, tutor, licencia, notas, activo, licenciaMaster (`true`\|`false`), categoriaManual (text; overrides the calculation) |
| Grupos | id, nombre, categoria, entrenador |

## Modules (each agent owns ONLY its own files)
- `js/config.js` — `GOOGLE_CLIENT_ID` (live binding: `BUILTIN_CLIENT_ID` or `localStorage['cnl:clientId']`), `setClientId(v)`, `isValidClientId(v)`, `SCOPES` (only `drive.file`), `CALENDAR_SCOPE`, `DRIVE_FOLDER='cnl'`, `PREFS_FILE`, `APP_VERSION`.
- `js/schema.js` — `SHEETS` (name->columns; no users sheet), `CATEGORIAS`, `newId()`. There is no `ROLES`.
- `js/store.js` — data:
  `await store.init(clubRef)`, `store.list(sheet)`->array, `store.get(sheet,id)`, `store.upsert(sheet,row)`->row (generates an id if missing), `store.remove(sheet,id)`, `store.on(fn)` (change/status event), `store.status` (`'sincronizado'|'pendiente'|'error'|'offline'`), `store.sync()`, `store.exportXlsx()`, `store.importXlsx(file)`, `store.club` (config object), `store.setClub(obj)`, `store.refresh()` (checks for remote changes), `store.clubRef` (`{name,id}`), `store.guardarXlsxEnDrive()`. `store.init` requires `{id,name}` (club file in Drive): there is no local mode.
- `js/infrastructure/driveConnection.js` (`js/auth.js` is a thin compatibility re-export) — `init()`, `connect({interactive=true, clientId?})` (interactive: Google's consent window, throws with a stable `code` from `domain/erroresGoogle.js` and `origin`; silent: renews without UI and returns `true|false`), `disconnect()` (revokes tokens, forgets the flag), `isConnected()` (previous authorization), `state` (`disconnected|connecting|connected|expired`), `enabled` (there is a Client ID), `token()`, `ensureToken()` (silent renewal), `tokenForScope(scope, {interactive, force})` (Calendar), `markExpired()`/`expired`/`onExpired(fn)`, `onChange(fn)`. There is no `user`, `signIn`, `signOut` or role.
- `js/infrastructure/demoStorage.js` + `js/application/modoService.js` + `js/modo.js` — **demo mode**: `demoStorage` implements the club-file port of `drive.js` (`meta/read/write/renameClub`, no backups, no folders/uploads) over `localStorage` `cnl:demo:*`; `store.init(ref, {demo})` / `store.initDemo()` run the store on it (`store.mode === 'demo'`, mirror prefix `cnl:demo:club:`, no polling); `crearModoService({store, demo, conexion, bandera, ahora})` -> `enterDemo()` (creates and seeds with `store.seedDemo({hoy})` the first time), `exitDemo()` (erases all demo data), `connectDrive()` (authorizes Drive and then drops the demo, so the real club starts empty).
- `js/drive.js` — Drive API v3 (`drive.file`): `ensureFolder(name, parentId)`, `ensureFolderPath(['entrenos'])`, `findFile`, `upload({name,mimeType,body,parentId,id,appProperties})`, `renameFile`, `deleteFile`, `listClubs()`, `createClub(name)`->`{id,name,url,rev}`, `renameClub`, `meta(id)`->`{rev,modifiedTime,name}`, `read(id)`->`{doc,rev,name}`, `write(id,doc)`->`{rev}`, `leerPreferencias()/guardarPreferencias(obj)`, `preferencias` (port `{leer, escribir}`), `fileUrl/folderUrl`, `reset()`. Errors carry `status`, `code` (`api-desactivada` with `enlace`, `sin-permiso`, `sesion-caducada`, `limite`, `no-encontrado`, `sin-conexion`) and `offline`.
- `js/sheetdata.js` — pure: `dataToDoc`, `docToData`, `hashData`, `mergeData`, `isEmptyData`.
- `js/preferencias.js` + `js/application/preferenciasService.js` + `js/domain/preferencias.js` — user preferences (see Persistence): `preferencias.get(key, def)`, `set(key, value)`, `conectar({remoto, email})`, `desconectar()`, `flush()`, `sincronizar()`, `volverLaRed()`, `on(fn)`, `estado`, `pendientes`, `comoAlmacenamiento(prefix)`.
- `js/application/asistenteClub.js` + `js/views/acceso.js` — first-run wizard, start screen (*Conectar Google Drive* / *Probar la demo*), *Configuración necesaria*, club selector and Google error help.
- `js/ui.js` — helpers: `h(tag, attrs, ...children)`, `modal({title, body, actions})`, `toast(msg)`, `confirmDialog(msg)`, `formFields(def, values)`, `fmtDate`, `fmtTime(ms)` (mm:ss.cc), `parseTime(str)`.
- `js/router.js` — hash router `#/nadadores`, `#/nadadores/<id>`; `registerRoute(name, loader)`.
- `js/app.js` — thin entry: calls `iniciar()` of `js/presentation/shell/boot.js` (see *Shell and PWA* below). The start flow, the shell (bottom bar on mobile, sidebar on desktop), the club theme (CSS vars `--c-primary`, `--c-secondary`) and the language <-> preferences link live in `js/presentation/shell/`. No roles: every module is always available.
- `js/views/<module>.js` — `export async function render(container, params, ctx)` where `ctx = {store, auth, ui}`. Modules: `inicio`, `nadadores`, `entrenamientos`, `asistencia`, `cargas`, `marcas`, `comunicaciones`, `club` (identity, where the data is stored, Excel copies, preferences, switch club).
- `css/app.css`, `index.html`, `manifest.webmanifest`, `sw.js` (generated list, see below), `icons/`.
- `vendor/xlsx.full.min.js` — vendored SheetJS (global `XLSX`), loaded with `<script>` in index.html and cached by the SW.
- `vendor/jspdf.umd.min.js` and `vendor/jspdf.plugin.autotable.min.js` — jsPDF + jspdf-autotable (production npm dependencies copied by `scripts/vendor.mjs`; Dependabot updates them and CI checks that `vendor/` is in sync). They are **not** loaded in `index.html`: `js/infrastructure/pdfEntreno.js` injects them with `<script>` the first time a PDF is requested and the SW precaches them.

## Calendar (layered architecture)
- `js/domain/calendario.js` — **pure** (no DOM, network or storage): dates, event sources (`FUENTES_EVENTOS`, extensible with `registrarFuente`; today Entrenamientos sessions and `AsignacionesCalle` expanded per week), filters by group and pool (`filtrarEventos`), colours, iCalendar generation (`generarICS`, `escaparTexto`, `plegarLinea`, `generarVTimezone`), Google event body (`aEventoGoogle`) and `diffSync`.
- `js/application/calendarioService.js` — `crearCalendarioService({store, auth, storage, cliente, ahora, etq})`: joins store and domain; exports and synchronizes (the sync map goes to the Drive preferences). Everything is injectable.
- `js/infrastructure/googleCalendar.js` — `crearClienteGoogleCalendar({fetch, getToken, sleep})`: insert/update/delete/listManaged with retries (429, quota 403, 5xx, network; `Retry-After`), token renewal on 401 and errors with `code` (`auth|permisos|api-desactivada|limite|no-existe|red|servidor`).
- `js/views/calendario.js` — presentation only (`ctx.cal` allows injecting the service/download in tests).
- **Time zone**: `Club.zonaHoraria` (IANA, default `Europe/Madrid`). The `.ics` uses `DTSTART;TZID=` + a `VTIMEZONE` generated with `Intl` (real transitions of the range, no RRULE; no tz database). Events without a time are all-day.
- **Google**: `auth.tokenForScope(CALENDAR_SCOPE)` (incremental consent, token in memory; `CALENDAR_SCOPE` is outside `SCOPES`). Primary calendar + `extendedProperties.private.cnlId/cnlClub`; map per club in `cnl/preferencias.json` (`calSync.*`); only vanished future events are deleted (past ones are kept).

## Pool planning (layered architecture)
- `js/domain/planificacion.js` — **pure** (no DOM, store, fetch or i18n): normalisation, `validarPiscina`, overlaps, `detectarConflictos(datos, {huecos})` and `conflictosDe(candidata, datos)` (return `{tipo, severidad: error|aviso|info, asignaciones, params}`; texts are translated in the view with `plan.c.<tipo>`), grid (`rangoDia`, `franjas`, `niveles`, `delDia`, `ocupacion`), `ajustarAlReducir` (trimming when the number of lanes is reduced) and `sugerirDistribucion` (deterministic: groups by number of swimmers, first free hour/lanes without errors).
- `js/application/planificacionService.js` — `crearPlanificacionService(repo)`: the repository (`list/get/upsert/remove`, e.g. the store) is injected. It blocks saving when there are errors and requires `forzar` for warnings.
- `js/views/planificacion.js` — presentation only (lanes x time slots grid, full week, forms, conflict panel, suggestion, printing via `@media print`). Own styles with prefix `pl-`.
- Rules: errors = overlapping lane, same group or coach at the same time, lane out of range, outside opening hours, invalid time, no group; warnings = lane capacity exceeded, no coach; info = free gaps. The stored data (sheets `Piscinas`, `AsignacionesCalle`) is neutral/in Spanish.

## Season planning (layered architecture)
- Vocabulary: **Fase** = macrocycle, **Semana** = microcycle (Monday to Sunday). The Planning tab has two sections (`#/planificacion` = Season, `#/planificacion/piscina` = Pool) mounted in `js/views/planificacion.js`.
- `js/domain/temporada.js` — **pure** (no DOM, store, network, i18n or clock): normalisation of the sheets `Temporadas`, `Fases`, `SemanasPlan` (deterministic id `sp-<season>-<monday>`; only edited weeks are stored, the rest is generated with `generarSemanas`) and `EventosTemporada`; phase assignment by dates, validations (`validarPlan`: overlapping phases = error, gaps, phases/events outside the season), classification of the plan lines by content (`volumenPlanSesion`, the **single point** that splits the volume of a plan among contents), actual aggregates (`agregarPlanes`, `agregarCargas`), `resumenSemanas` (planned vs actual, deviation ±10 %, status), `totales` per phase, `sugerencias` (accumulated content, weeks before A/B competitions, tapering, weeks without a plan), tools (`ajustarVolumenes`, `desplazarPlan`, `aplicarPlantillaFase`, `copiarPlanSemana`), `eventosDeTemporada` + `FUENTE_CALENDARIO` (registered with `registrarFuente` in `calendarioService`) and `temporadaDemo`.
- Volumes are metres per swimmer and week. The **actual** volume comes from Cargas (average per swimmer) or, if there is none, from the training plans (Entrenamientos + EntrenoLineas, done and planned); the source can be forced. With `Temporadas.grupoId` only the sessions and swimmers of that group count.
- `js/application/temporadaService.js` — `crearTemporadaService(repo, {ahora, nombreFase})`: injected repository (store or memory); CRUD of seasons (one active, cascade delete), phases (overlaps require `forzar`), events and weeks, `resumen` (complete model of the view) and tools with preview.
- `js/views/temporada.js` and `js/views/temporada-grafico.js` — presentation only. Own SVG chart (bars stacked by content, planned line, phase bands, markers A=diamond/B=square/C=circle with their letter, keyboard focus and tooltip), timeline (Gantt) and table; on mobile, a list of weeks with mini-bars. Styles with prefix `tp-`; texts in `js/locales/temporada.{es,en,it}.js`.

## Detailed training plan and PDF (layered architecture)
- `js/domain/entreno.js` — **pure** (no DOM, store, fetch or i18n): tolerant numbers (`num`), send-offs (`parsearSalida`: cycle `C/1'10"` and rest `d/15"`, with canonical form), calculation (`distanciaBloque` = series x distance; `agruparSets` -> Set distance; `totales` -> minutes and metres of the session; `resumen`), validation (`validarLinea`, `validarSesion`: non-numeric series/distance/time = error; unrecognised send-off, target volume, duration and difference with the recorded load (`cargaRegistrada`, 10 % tolerance) = warning), draft editing (`anadirSet/Fila`, `quitar*`, `mover*`, `duplicarSet/Fila`, `renumerar`), `duplicarSesion`, templates (`PLANTILLAS`, `lineasDePlantilla`), `planDemo`, `sugerencias` (autocomplete) and file names (`Alevin-2026-10-15-jueves.pdf`).
- `js/domain/desglose.js` — **pure**: split of each row among several **contents** and **styles** and their totals. Decision: the metres of a component are `series x metrosPorRep` (4x100 freestyle = 400 m of freestyle; the 100 m are per repetition and are shown as «m/rep»); the session total remains the sum of the block distances. A single auto component receives the whole distance; auto components without metres share the remainder equally; manual (metres or %) always wins and, when set, auto components with metres are rebalanced proportionally (`fijarReequilibrando`); what is unassigned counts as «no content» and an excess is scaled proportionally (both give a warning: `validarReparto`, `asignarResto`). `parsearEjercicio`/`autocompletarLinea` understand `4x100 Crol. 75 AeL-25 Tope`, `8x50 (25 Sprint+25 AeL)`, `6x100 AeL`, `3x(200 AeM + 100 AeI)` with the aliases of `TiposCarga.alias` (`AeL`, `Tope`, `Pn`...). `desgloseSesion(lineas, {tipos})` -> `{totalM, porContenido:[{contenido,tipoId,metros,pct}], porEstilo, porSet, filas}` (% with 1 decimal that add up to 100; old rows without components go to the content of their objective) and `volumenPorContenido(sesiones)` (used by `temporada.volumenPlanSesion`). `textoResumen`/`textoEjercicio` give «Volumen total: 400 m (AeL 300 m · Sprint 100 m) · Por estilo: Crol 400 m».
- `js/application/entrenoService.js` — `crearEntrenoService(repo, {genId, club})`: injected repository. `guardarPlan` (replaces the lines; errors prevent saving, warnings do not), `eliminarSesion` (also deletes the plan), `duplicarSesion`, `copiarPlan`, `planDesdeSesion/Plantilla`, `sugerencias`, `desglose`, `registrarCargasDesdePlan` (one load per content and swimmer with the metres of the plan, without duplicates), `ficha`/`fichasSemana` (data for the PDF, with `desglose` and catalogue; they accept an unsaved draft).
- `js/infrastructure/pdfEntreno.js` — `generarPdfEntreno(fichas, {t, locale, lib})`: A4 landscape, header with the club colours and logo (light or dark text depending on contrast), jspdf-autotable table with sets separated by a thick line, Set distance in the last row of each set, TOTALES row, repeated headers and several pages if needed (the font size shrinks until it fits on one), footer with club, generation date and page. Texts come from `js/locales/entreno.{es,en,it}.js`. The library is loaded lazily (`cargarLibreria`; `usarLibreria` for tests). `js/infrastructure/driveEntrenos.js` saves the PDF in `cnl/entrenos` with `drive.ensureFolderPath/findFile/upload` (updates it if it already exists).
- `js/views/entreno-editor.js` (set-based editor, mobile first, live totals, templates, copy from another session, read-only view), `js/views/entreno-acciones.js` (download, preview, print, Drive) and buttons in `js/views/entrenamientos.js`.

## Loads and training contents (layered architecture)
- `js/domain/cargas.js` — **pure** (no DOM, store or i18n): predefined catalogue (`CATALOGO_PREDEFINIDO`, 10 contents with stable id `tc-<key>`), `normalizarNombre` (no accents/case/spaces), `validarTipo`, seeding (`sembrarCatalogo`), migration (`migrarHeredados`, `prepararCatalogo`), weekly aggregates (`agregarSemana`: average per swimmer with load, per content and per day) and objective evaluation (`evaluarObjetivo`, `evaluarSemana`).
- `js/application/cargasService.js` — `crearCargasService(repo, {generarId})`: injected repository. Create/edit/activate/move/delete/merge contents, `registrarCarga` (validates swimmer, date, metres, RPE, minutes, active content and optional session), `semana()`.
- `js/views/cargas-contenidos.js` — "Contenidos de entrenamiento" manager (used in Cargas and Configuración) and presentation utilities (`chip`, `fmtM`). `js/views/cargas.js`, `inicio.js` and `nadadores.js` are presentation only.
- **Decisions**: `Cargas.tipo` stores the NAME of the content (a Spanish value, compatible with old data); comparison is by normalised name and renaming a custom content updates its loads. Predefined contents can be deactivated/edited (description, colour, objectives) but not deleted or renamed; a content with loads is not deleted (it is deactivated or merged into another). The i18n keys are `tc.<key>.nombre|desc`; custom ones are shown as typed.
- **Seeding and migration** (`store.ensureCatalog`, on open/sync/import/clear): adds the missing predefined contents (by id, without duplicating or overwriting edits); old Cargas/ObjetivosCarga types that do not match the catalogue (Aeróbico, Velocidad, Fuerza...) become "legacy" custom contents with their original name (Piernas and Técnica match the predefined ones); the objectives of ObjetivosCarga become the content's minSemanalM/maxSemanalM (without overwriting one already defined) and those rows are removed. Loads are not rewritten.
- **Objective criterion** (Cargas and Inicio): average metres per swimmer with a load that week (or of the chosen swimmer) against the per-swimmer objective.

## Categories by season (layered architecture)
- `js/domain/categorias.js` — **pure** (no DOM, I/O or clock; the date always arrives as a parameter): `temporadaDe(fecha)` (1 Sep -> 31 Aug; returns the start year), `etiquetaTemporada`/`parseTemporada`, `tablaCategorias(temporada, {sexo, config})` (birth-year ranges **by offset from the start year**: default ages Pre-Benjamín 8, Benjamín 9-10, Alevín 11-12, Infantil 13-14, Junior 15-17, Absoluto 18+), `rangoAnios`, `categoriaDe({fechaNacimiento, sexo, licenciaMaster}, temporada, config)` (never throws: invalid dates -> no category; younger than the table -> Pre-Benjamín + warning `por-debajo-edad`; Master = master licence AND minimum age), `categoriaVigente` (the manual one wins) and `cambiosDeTemporada(nadadores, de, a)`. The configuration (`normalizarConfig`/`validarConfig`) holds the age table **per sex** (identical for F and M by default) and `edadMinimaMaster` (25); a broken configuration is replaced by the default one.
- `js/application/categoriasService.js` — `crearCategoriasService(repo, {ahora})`: injected repository (`list/upsert` + `club/setClub`, e.g. the store) and clock. `recalcular(temporada)` updates `Nadadores.categoria` for those without `categoriaManual` and returns the summary; `alAbrirClub()` recalculates only if the current season differs from `temporadaAplicada` (called from `app.js` after `store.init` and after importing an Excel); `guardarNadador` materialises the category on create/edit; `previsualizar` feeds the live form; `previsualizarCambio`/`cambiarTemporada` and `guardarConfig`/`restablecerConfig`.
- `js/views/categorias-panel.js` — Configuration panel (calculated table, season selector, change preview, on-demand recalculation and per-sex rules) and compact table in Nadadores; `js/views/nadadores.js` — live automatic category (read-only) + *Categoría manual* + *Licencia máster*, *manual* badge in the list and profile. Texts in `js/locales/categorias.{es,en,it}.js` (prefix `categorias.`).
- **Club keys** (sheet *Club*): `temporadaActual` (empty = automatic from today's date; or a fixed `2026-2027`), `temporadaAplicada` (last season for which categories were recalculated), `categoriasConfig` (JSON of the configuration; empty = defaults). **Nadadores**: `licenciaMaster` (`true`|`false`) and `categoriaManual` (text; if present, it wins). Compatible migration: old clubs do not have these columns (they read as empty) and are recalculated on open.
- Demo data (`store.seedDemo`) sets the birth year as `season year of the clock − age` and obtains the category with `categoriaDe`, not by hand.

## Individual use (no roles, no sharing)
The person who connects Drive is the coach and can do everything. There are no roles, no `Usuarios` sheet, no sharing/joining sheets and no *Mi espacio* view; `auth.role()` and the services' `puedeEditar` option no longer exist. The only read-only state is `store.soloLectura`, set when the club file was written by a newer version of the app. Multi-device use is the same person on several devices: changes are merged per field (see *Concurrency*). The *Comunicaciones* sheet and the *Avisos y notas* view hold the coach's own notices and notes (they can be copied to be passed on elsewhere); the app never sends them to anyone.

Business rules left the shell and live in the application layer, with every concrete dependency injected:

- `js/application/sesionService.js` — `crearSesionService({auth, drive, prefs, CLAVES, store, banderas, limpiarDatosLocales, espera, log})`: `resolveStartMode()` / `decidirArranque()` (drive | demo | demo-cerrada | start | config | inicio | tutorial; the demo rule is `demoDisponible()` in `modoService.js`: only without a Client ID), `resolverClub()` (-> abrir | crear | elegir | error), `reconectar()`, `cerrarSesion({preguntarPendientes})` (upload with a deadline, ask when it could not, revoke, erase local mirrors; the demo never uploads). Entering and leaving the demo is `application/modoService.js`.
- `js/application/avisosService.js` (+ `domain/avisos.js`) — `crearAvisosService({listar, ahora, visto})`: `contarNoLeidos()` for the bell (notices of the last 7 days written after the last visit) and `marcarVistos()`.

Ports used by the shell services (browser implementations are in `boot.js`):

| Port | Shape | Browser adapter |
|---|---|---|
| `banderas` | `{selectorForzado(), limpiarSelectorForzado(), demoGuardada()}` | `sessionStorage['cnl:elegir']`, `localStorage['cnl:mode']` |
| `visto` | `{leer(), escribir(isoDate)}` | `localStorage['cnl:avisos-visto']` |
| `ahora` | `() => Date` | `new Date()` |
| `limpiarDatosLocales` | `() => Promise` | `cache.js` |
| `espera` | `(ms) => Promise` | `setTimeout` |

**Service worker.** `sw.js` is hand-written except the block between `>>> GENERATED` and `<<< GENERATED`, which `scripts/generate-sw.mjs` writes (`npm run build:sw`): the precache list (index, manifest, `css/**` including `css/views/*.css`, `js/**`, `icons/**`, `vendor/**`; `js/infrastructure/fakeGoogle.js` is excluded on purpose) and a `VERSION` that is a content hash (text normalised to LF, so CRLF and LF checkouts agree). `npm run check` runs `generate-sw.mjs --check`: it fails when the list is stale and when an `import`, a `useStyles('<name>')` stylesheet or an `index.html` reference points to a missing or non-precached file. Strategies: stale-while-revalidate for HTML/JS/CSS, cache-first for `vendor/` and `icons/`; only same-origin GET is handled, so Google/Drive/Identity Services always go to the network. A required file that fails to precache aborts the install (the old worker keeps running); `vendor/*` are optional. There is no `skipWaiting` on install: the page shows "A new version is available - Reload" and sends `SKIP_WAITING` on the user's click, then reloads once the new worker controls it.

## Rules
- Do not touch files owned by other agents. Do not run git commands (the orchestrator commits).
- Simple code, minimal comments. Always escape user text (use `h()`/textContent, never innerHTML with data).
