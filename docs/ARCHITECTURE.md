# CNL Plataforma — Arquitectura (contrato entre módulos)

PWA 100% estática (GitHub Pages), sin build, JavaScript ES modules, sin frameworks.
**Todas las rutas deben ser RELATIVAS** (`./js/app.js`), porque Pages sirve bajo `/cnsa-management-platform/`.
UI en español. Mobile-first.

## Persistencia (Google Drive, scope único `drive.file`)
**Individual-use app.** There is **no sign-in and no user identity**: the person only *connects Google Drive* (OAuth authorization, single scope `drive.file`; no `openid`/`email`/`profile`, no `userinfo` call, no name/e-mail/picture is ever shown or stored). Their data is saved in **their own Google Drive** (`cnl` folder) only so that it persists and is available on all of their devices (e.g. computer and phone). Drive is **not** a shared database between users: there is no server, database, sharing, roles or multi-user support, and the app shares data with nobody. Swimmers, groups, etc. are records the person manages, not app users. Disconnecting Drive clears the local cache of that device. Without a connected Drive the app offers a **demo mode** (sample data kept only in the browser under `cnl:demo:*`, never sent to Drive, clearly labelled; see the demo-mode bullet in the module list below).
- **Conexión con Drive** (`js/infrastructure/driveConnection.js`, Google Identity Services token flow, sólo autorización). Scope: `https://www.googleapis.com/auth/drive.file` y nada más. Es el único permiso de datos: la app sólo ve los ficheros que ella misma crea; no es sensible ni requiere verificación de Google. **No se usa la API de Sheets.** Sólo hay que activar Drive API (y Calendar API si se sincroniza el calendario; su scope `calendar.events` es incremental y no forma parte de `SCOPES`).
- **Client ID**: constante `BUILTIN_CLIENT_ID` de `js/config.js` (the deployment owner sets it once; end users only connect Drive). Si está vacía, el shell muestra *Configuración necesaria* (tutorial + campo para probar un ID, que queda sólo en `localStorage['cnl:clientId']`); la demo sigue disponible. No puede vivir en Drive: hace falta antes de conectar.
- **Flujo de arranque** (`presentation/shell/boot.js`, `application/sesionService.js`): `resolveStartMode()` -> `'drive'` (hay autorización previa; gana a una bandera de demo antigua) | `'demo'` (`localStorage['cnl:mode']='demo'`) | `'start'` (pantalla de inicio: *Conectar Google Drive* / *Probar la demo*; sin Client ID -> *Configuración necesaria*). Modo drive: `preferencias.conectar` + `drive.listClubs()` -> 0 clubes: asistente de club (`views/acceso.js` + `application/asistenteClub.js`, club vacío); 1 club o el `ultimoClub`: se abre; varios: selector -> shell. Sin conexión se usan la caché y la lista de clubes espejo de las preferencias.
- **Fichero del club** `cnl/<NombreClub>.json`: `{ version: 1, club: {clave: valor}, hojas: { Nadadores: [fila...], ... } }` (secciones y columnas de `schema.js`, `sheetdata.dataToDoc/docToData`). Marcado con `appProperties.cnl='club'` para listarlo (`drive.listClubs`); se renombra al cambiar el nombre del club.
- **Concurrencia (otro dispositivo)**: la revisión es `md5Checksum` (o `modifiedTime`). `store.refresh` (polling ~30 s, pestaña visible) compara `drive.meta(id).rev` con la última conocida y, si cambió y no hay ediciones locales, recarga. `store.sync` (debounce 1,5 s, botón *Sincronizar*, evento `online`) comprueba `meta` antes de escribir y, si hay cambios locales y remotos, hace **fusión de tres vías por fila (`id`)** entre `base` (última versión sincronizada), lo local y lo remoto (`sheetdata.mergeData`; conflicto en la misma fila: gana lo local). La escritura sobrescribe el contenido (PATCH `uploadType=media`).
- **Caché local** (`localStorage['cnl:club:<id>']`) como espejo con la marca `dirty` y la `base`: cola de cambios pendientes sin conexión. Estados de `store.status`: `sincronizado|pendiente|error|offline`.
- **Preferencias** `cnl/preferencias.json` (`{version, valores, marcas}`; `domain/preferencias.js` puro, `application/preferenciasService.js` con caché `localStorage['cnl:prefs']`, debounce, cola offline y fusión por clave con marca de tiempo; instancia única en `js/preferencias.js`). Claves: `idioma`, `ultimoClub`, `clubes` (espejo de la lista), `tutorial`, `calendario.vista|ventanaDias|alarmaMin`, `calSync.<clave>` (mapa de sincronización con Google Calendar). Una versión futura del fichero no se degrada ni pierde claves desconocidas. El idioma se sincroniza en cuanto hay sesión (lo elegido antes del login gana por marca de tiempo).
- **Errores de Google** (`domain/erroresGoogle.js`, `views/acceso.js#errorGoogle`): popup bloqueado/cerrado, cuenta que no es usuario de prueba, origen no autorizado (se muestra el origen actual para copiarlo), API de Drive desactivada (con enlace de activación), 401 (renueva el token una vez; si no puede, *La conexión con Drive ha caducado: Reconectar*), 403/404/429 y sin red (`e.offline`). Desconectar Drive **revoca** los tokens y limpia cachés.
- **Carpeta `cnl` previa**: con `drive.file` la app no ve una carpeta `cnl` hecha a mano; `drive.ensureFolder` busca la suya y, si no existe, la crea (una sola, la más antigua si hubiera varias). La UI y el tutorial lo explican.
- **PDFs** en `cnl/entrenos/` (`drive.ensureFolderPath(['entrenos'])` + `drive.upload`) y copias `.xlsx` en `cnl/` (`store.guardarXlsxEnDrive`). Exportar/importar `.xlsx` (`store.exportXlsx/importXlsx`) sigue siendo la copia de seguridad.

### Data integrity (`store.js`, `drive.js`, `sheetdata.js`, `cache.js`)
- **Concurrency**: `meta`/`read` request Drive's `version` (a monotonic integer). After the PATCH, if the returned version is not read+1, another device wrote in between: the previous revision is fetched (`revisions.list` + `alt=media`), merged with `mergeData` and rewritten (up to 5 rounds). Rotating daily backup `cnl/backups/<club>-YYYYMMDD.json` (last 14, holding the content from before the first write of the day).
- **Per-field merge** (3-way base/local/remote): per-row logical stamps (Lamport clock `n@tab`, no wall clock) in `doc.sync`, tombstones for deletions (GDPR-purge tombstones are permanent), an edit beats a deletion, and orphan cleanup (Cargas/Asistencia/Marcas/EntrenoLineas/Fases... of deleted parents).
- **File**: `version` greater than `DOC_VERSION` => read-only with a notice; unknown sheets, columns and keys are preserved (`extra`). Unreadable JSON or an emptied file ({}/null while local data exists) => recovery screen (local copy / latest backup / open in Drive); nothing is overwritten without a decision. Types are normalised on read/import (club values text only, phone/licence as text, Excel serial dates to ISO).
- **Network**: `gfetch` has a 30 s AbortController, retries with exponential backoff and `Retry-After` (429/5xx), and distinguishes `storageQuotaExceeded` (`cuota-drive`); a single token request in flight with a deadline; a 90 s watchdog in `store.sync`; polling with growing delay after errors.
- **Local cache**: `saveCache` is debounced (200 ms) and flushed when the tab is hidden/closed; localStorage overflows to IndexedDB; if neither fits the status becomes `error` plus a notice. Two tabs merge through the `storage` event (and `navigator.locks` serialises syncing).
- **Disconnect Drive** (`sesionService.cerrarSesion` + `driveConnection.disconnect`): uploads what is pending (with a deadline); if it cannot, a dialog offers download copy / discard / cancel; afterwards it revokes the tokens and always erases `cnl:club:*`, `cnl:drive-auth`, `cnl:prefs`, `cnl:cal-sync:*`, the demo namespace and the legacy `cnl:user`/`cnl:token` (`cache.limpiarDatosLocales`).
- **Backup / restore** (`domain/backup.js`, `application/backupService.js`, `infrastructure/backupCrypto.js`, `infrastructure/backupDrive.js`, `composicion/backup.js`, `views/backup-panel.js`): the complete lossless copy in one file. Format `cnl-backup` v1 = `{format, formatVersion, appVersion, docVersion, createdAt, club:{name,data}, sheets:{all sheets incl. unknown}, extra:{top}, preferences:{user-level only}, counts, checksum}`; the checksum is SHA-256 over the canonical (key-sorted) JSON without the checksum field, computed through an injected hash port. Optional envelope `cnl-backup-encrypted` (PBKDF2-SHA256 + AES-256-GCM; the parameters are authenticated data). Restore semantics: (1) validate (format, version, checksum, shape, limits); (2) automatic safety copy first (Drive `cnl/backups/<club>-restore-*.json`, last 5; demo mode: in memory + download), nothing is touched if it fails; (3) *replace* = `upsertMany` of new/changed rows + `removeMany` of the rest (tombstones, so other devices converge), *merge* = `mergeData(null, current without tombstones, backup)` (current wins on conflicts, nothing removed); unknown sheets/columns/keys go through `store.aplicarExtras`; (4) rows failing `validarFila` and rows with permanent GDPR tombstones (and their children) are skipped and reported; the club name never changes; (5) `store.migrar()` (legacy objectives/catalogue), category recalculation, user preferences; (6) if applying fails the safety copy is applied back. `store.documento()` exposes the club document. Plain daily/import copies from Drive and the "download JSON copy" file are accepted as sources. The service imports `sheetdata.js`/`schema.js` (pure, domain-target legacy files) directly; everything else is injected. GDPR: a backup holds personal data of minors; copies already downloaded are not affected by an erasure (the UI says so); `drive.listarBackups(name, {todos:true})` lets `purgarNadador` delete the Drive daily, pre-import and pre-restore copies.
- **GDPR**: `store.exportNadador(id)`, `store.purgarNadador(id)` (cascade, permanent tombstone, deletes Drive .xlsx copies, backups and old revisions), validation in `upsert` (`domain/validacion.js`), import with preview, prior backup and limits (20 MB / 50,000 rows).

### Herramienta de pruebas: `js/infrastructure/fakeGoogle.js`
Adaptador en memoria que sustituye a la conexión (`driveConnection`) y a `drive` (mismas interfaces: conexión simulada `connect/disconnect/isConnected/token`, `ensureFolder`, `listClubs`, `createClub`, `meta/read/write`, `leerPreferencias/guardarPreferencias`, `upload`, `findFile`...). It is activated **only** with `window.__CNL_TEST__` (injected by Playwright with `addInitScript`, valid on any host) or with `localStorage['cnl:test']='1'` **and** `location.hostname` being localhost/127.0.0.1 (`js/infrastructure/entornoPruebas.js`; the shell imports it dynamically; it is not downloaded in production). It also simulates Drive's `version`, revisions, `cnl/backups`, permanent deletion and hooks (`escribirAntes`, `corromperClub`, `vaciarClub`, `caducarSesion`). Opciones: `conectado` (alias `sesion`), `demo` (siembra `store.seedDemo` una vez en un club del Drive simulado; no es el modo demo del producto), `sinClientId`, `errorConexion` (alias `errorLogin`), `fallos`; no hay opción de usuario. Espeja su estado en `localStorage['cnl:test:drive']` para sobrevivir a recargas y expone `window.__CNL_FAKE__` (`clubs()`, `prefs()`, `archivos()`, `editarClubExterno`, `conectar()`, `desinstalar()`). Lo usan `tests/helpers/app.js`, los tests unitarios y los pasos de Cucumber.

## Secciones del fichero del club = pestañas del Excel exportable (fila 1 = cabeceras exactas, `id` = string único)
En `cnl/<Club>.json` la sección `club` es el objeto de la fila *Club* (clave/valor) y cada entidad es un array en `hojas`; el Excel exportable usa las mismas columnas.
| Hoja | Columnas |
|---|---|
| Club | clave, valor  (nombre, lema, logo(dataURL), colorPrimario, colorSecundario, zonaHoraria) |
| Nadadores | id, nombre, apellidos, fechaNacimiento, sexo, categoria (vigente, calculada), grupoId, email, telefono, tutor, licencia, notas, activo, licenciaMaster (`true`\|`false`), categoriaManual (texto; manda sobre el cálculo) |
| Grupos | id, nombre, categoria, entrenador |
| Entrenamientos | id, fecha, hora, duracionMin, grupoId, titulo, descripcion, estado (`planificado`\|`realizado`), piscina, volumenMin, volumenMax, enfoque, tipoSesion, materialDia, notasGenerales |
| EntrenoLineas | id, entrenamientoId, set, orden, tiempoMin, objetivo, bloque, series, distancia, salida, ejercicio, material, notas, componentes (JSON `[{contenido, metrosPorRep, modo:'auto'|'manual', pct?}]`), estilo (nombre o JSON `[{estilo, metrosPorRep}]`) (plan detallado de la sesión: una fila por línea, agrupadas por `set`) |
| Asistencia | id, entrenamientoId, nadadorId, estado (`presente`\|`ausente`\|`justificado`), nota |
| Cargas | id, entrenamientoId (sesión opcional), nadadorId, fecha, metros, rpe, minutos, tipo (= nombre del contenido), notas |
| TiposCarga | id, nombre, descripcion, color (`#rrggbb`), categoria (`intensidad`|`especifico`|`personalizado`), orden, activo, predefinido, minSemanalM, maxSemanalM (objetivos por nadador, opcionales) |
| ObjetivosCarga | LEGADO (id, tipo, minSemanalM, maxSemanalM): se migra a TiposCarga y la fila se elimina |
| Marcas | id, nadadorId, fecha, prueba, piscina (`25`\|`50`), tiempoMs, competicion, notas |
| Comunicaciones | id, fecha, titulo, texto, grupoId (vacío = todos), autor |
| Piscinas | id, nombre, longitudM (`25`\|`50`), numCalles, intervaloMin (`15`\|`30`), maxPorCalle, horario (JSON por día: `{"1":{"abre":"07:00","cierra":"22:00"},...,"7":null}`; 1=lunes, `null`=cerrado) |
| AsignacionesCalle | id, piscinaId, dia (1-7), fecha (vacía = semanal; con valor = excepción puntual, el día se deriva de la fecha), horaInicio, horaFin (`HH:MM`), calleDesde, calleHasta, grupoId, entrenadorId (nombre del entrenador), notas |

Categorías en orden: Pre-Benjamín, Benjamín, Alevín, Infantil, Junior, Absoluto, Master. No se asignan a mano: se calculan por año de nacimiento, sexo y temporada (ver *Categorías por temporada*).

## Módulos (cada agente es dueño SÓLO de sus ficheros)
- `js/config.js` — `GOOGLE_CLIENT_ID` (binding vivo: `BUILTIN_CLIENT_ID` o `localStorage['cnl:clientId']`), `setClientId(v)`, `isValidClientId(v)`, `SCOPES` (sólo `drive.file`), `CALENDAR_SCOPE`, `DRIVE_FOLDER='cnl'`, `PREFS_FILE`, `APP_VERSION`.
- `js/schema.js` — `SHEETS` (nombre->columnas; sin hoja de usuarios), `CATEGORIAS`, `newId()`. No hay `ROLES`.
- `js/store.js` — datos:
  `await store.init(clubRef)`, `store.list(sheet)`->array, `store.get(sheet,id)`, `store.upsert(sheet,row)`->row (genera id si falta), `store.remove(sheet,id)`, `store.on(fn)` (evento de cambios/estado), `store.status` (`'sincronizado'|'pendiente'|'error'|'offline'`), `store.sync()`, `store.exportXlsx()`, `store.importXlsx(file)`, `store.club` (objeto config), `store.setClub(obj)`, `store.refresh()` (comprueba cambios remotos), `store.clubRef` (`{name,id}`), `store.guardarXlsxEnDrive()`. `store.init` exige `{id,name}` (fichero del club en Drive): no existe el modo local.
- `js/infrastructure/driveConnection.js` (`js/auth.js` is a thin compatibility re-export) — `init()`, `connect({interactive=true, clientId?})` (interactive: Google's consent window, throws with a stable `code` from `domain/erroresGoogle.js` and `origin`; silent: renews without UI and returns `true|false`), `disconnect()` (revokes tokens, forgets the flag), `isConnected()` (previous authorization), `state` (`disconnected|connecting|connected|expired`), `enabled` (hay Client ID), `token()`, `ensureToken()` (renovación silenciosa), `tokenForScope(scope, {interactive, force})` (Calendar), `markExpired()`/`expired`/`onExpired(fn)`, `onChange(fn)`. There is no `user`, `signIn`, `signOut` or role.
- `js/infrastructure/demoStorage.js` + `js/application/modoService.js` + `js/modo.js` — **demo mode**: `demoStorage` implements the club-file port of `drive.js` (`meta/read/write/renameClub`, no backups, no folders/uploads) over `localStorage` `cnl:demo:*`; `store.init(ref, {demo})` / `store.initDemo()` run the store on it (`store.mode === 'demo'`, mirror prefix `cnl:demo:club:`, no polling); `crearModoService({store, demo, conexion, bandera, ahora})` -> `enterDemo()` (creates and seeds with `store.seedDemo({hoy})` the first time), `exitDemo()` (erases all demo data), `connectDrive()` (authorizes Drive and then drops the demo, so the real club starts empty).
- `js/drive.js` — Drive API v3 (`drive.file`): `ensureFolder(name, parentId)`, `ensureFolderPath(['entrenos'])`, `findFile`, `upload({name,mimeType,body,parentId,id,appProperties})`, `renameFile`, `deleteFile`, `listClubs()`, `createClub(name)`->`{id,name,url,rev}`, `renameClub`, `meta(id)`->`{rev,modifiedTime,name}`, `read(id)`->`{doc,rev,name}`, `write(id,doc)`->`{rev}`, `leerPreferencias()/guardarPreferencias(obj)`, `preferencias` (puerto `{leer, escribir}`), `fileUrl/folderUrl`, `reset()`. Errores con `status`, `code` (`api-desactivada` con `enlace`, `sin-permiso`, `sesion-caducada`, `limite`, `no-encontrado`, `sin-conexion`) y `offline`.
- `js/sheetdata.js` — puro: `dataToDoc`, `docToData`, `hashData`, `mergeData`, `isEmptyData`.
- `js/preferencias.js` + `js/application/preferenciasService.js` + `js/domain/preferencias.js` — preferencias del usuario (ver Persistencia): `preferencias.get(clave, def)`, `set(clave, valor)`, `conectar({remoto, email})`, `desconectar()`, `flush()`, `sincronizar()`, `volverLaRed()`, `on(fn)`, `estado`, `pendientes`, `comoAlmacenamiento(prefijo)`.
- `js/application/asistenteClub.js` + `js/views/acceso.js` — asistente de primer arranque, pantalla de inicio (*Conectar Google Drive* / *Probar la demo*), *Configuración necesaria*, selector de club y ayuda de errores de Google.
- `js/ui.js` — helpers: `h(tag, attrs, ...children)`, `modal({title, body, actions})`, `toast(msg)`, `confirmDialog(msg)`, `formFields(def, values)`, `fmtDate`, `fmtTime(ms)` (mm:ss.cc), `parseTime(str)`.
- `js/router.js` — hash router `#/nadadores`, `#/nadadores/<id>`; `registerRoute(name, loader)`.
- `js/app.js` — thin entry: calls `iniciar()` of `js/presentation/shell/boot.js` (see *Shell and PWA* below). The start flow, the shell (bottom bar on mobile, sidebar on desktop), the club theme (CSS vars `--c-primary`, `--c-secondary`) and the language <-> preferences link live in `js/presentation/shell/`. No roles: every module is always available.
- `js/views/<modulo>.js` — `export async function render(container, params, ctx)` donde `ctx = {store, auth, ui}`. Módulos: `inicio`, `nadadores`, `entrenamientos`, `asistencia`, `cargas`, `marcas`, `comunicaciones`, `club` (identidad, dónde se guardan los datos, copias Excel, preferencias, cambiar de club).
- `css/app.css`, `index.html`, `manifest.webmanifest`, `sw.js` (generated list, see below), `icons/`.
- `vendor/xlsx.full.min.js` — SheetJS vendorizado (global `XLSX`), cargado con `<script>` en index.html y cacheado por el SW.
- `vendor/jspdf.umd.min.js` y `vendor/jspdf.plugin.autotable.min.js` — jsPDF + jspdf-autotable (dependencias npm de producción copiadas por `scripts/vendor.mjs`; Dependabot las actualiza y el CI comprueba que `vendor/` está sincronizado). **No** se cargan en `index.html`: `js/infrastructure/pdfEntreno.js` las inyecta con `<script>` la primera vez que se pide un PDF y el SW las precachea.

## Calendario (arquitectura en capas)
- `js/domain/calendario.js` — **puro** (sin DOM, red ni storage): fechas, fuentes de eventos (`FUENTES_EVENTOS`, extensible con `registrarFuente`; hoy sesiones de Entrenamientos y `AsignacionesCalle` expandidas por semana), filtros por grupo y piscina (`filtrarEventos`), colores, generación iCalendar (`generarICS`, `escaparTexto`, `plegarLinea`, `generarVTimezone`), cuerpo de evento de Google (`aEventoGoogle`) y `diffSync`.
- `js/application/calendarioService.js` — `crearCalendarioService({store, auth, storage, cliente, ahora, etq})`: junta store y dominio; exporta y sincroniza (el mapa de sincronización va a las preferencias de Drive). Todo inyectable.
- `js/infrastructure/googleCalendar.js` — `crearClienteGoogleCalendar({fetch, getToken, sleep})`: insertar/actualizar/borrar/listarGestionados con reintentos (429, 403 de cuota, 5xx, red; `Retry-After`), renovación de token ante 401 y errores con `code` (`auth|permisos|api-desactivada|limite|no-existe|red|servidor`).
- `js/views/calendario.js` — sólo presenta (`ctx.cal` permite inyectar servicio/descarga en pruebas).
- **Zona horaria**: `Club.zonaHoraria` (IANA, por defecto `Europe/Madrid`). El `.ics` usa `DTSTART;TZID=` + `VTIMEZONE` generado con `Intl` (transiciones reales del rango, sin RRULE; sin base de datos tz). Los eventos sin hora son de día completo.
- **Google**: `auth.tokenForScope(CALENDAR_SCOPE)` (consentimiento incremental, token en memoria; `CALENDAR_SCOPE` fuera de `SCOPES`). Calendario principal + `extendedProperties.private.cnlId/cnlClub`; mapa por club y cuenta en `cnl/preferencias.json` (`calSync.*`); sólo se borran los eventos futuros desaparecidos (lo pasado se conserva).

## Planificación de la piscina (arquitectura en capas)
- `js/domain/planificacion.js` — **puro** (sin DOM, store, fetch ni i18n): normalización, `validarPiscina`, solapes, `detectarConflictos(datos, {huecos})` y `conflictosDe(candidata, datos)` (devuelven `{tipo, severidad: error|aviso|info, asignaciones, params}`; los textos se traducen en la vista con `plan.c.<tipo>`), rejilla (`rangoDia`, `franjas`, `niveles`, `delDia`, `ocupacion`), `ajustarAlReducir` (recorte al bajar el nº de calles) y `sugerirDistribucion` (determinista: grupos por nº de nadadores, primera hora/calles libres sin errores).
- `js/application/planificacionService.js` — `crearPlanificacionService(repo)`: the repository (`list/get/upsert/remove`, e.g. the store) is injected. It blocks saving when there are errors and requires `forzar` for warnings.
- `js/views/planificacion.js` — sólo presenta (rejilla calles x franjas, semana completa, formularios, panel de conflictos, sugerencia, impresión por `@media print`). Estilos propios con prefijo `pl-`. Nadador: sólo lectura (su grupo si se puede identificar).
- Reglas: errores = calle solapada, mismo grupo o entrenador a la vez, calle fuera de rango, fuera de horario, hora inválida, sin grupo; avisos = capacidad por calle excedida, sin entrenador; info = huecos libres. Los datos guardados (hojas `Piscinas`, `AsignacionesCalle`) son neutros/en español.

## Planificación de temporada (arquitectura en capas)
- Vocabulario: **Fase** = macrociclo, **Semana** = microciclo (lunes a domingo). La pestaña Planificación tiene dos apartados (`#/planificacion` = Temporada, `#/planificacion/piscina` = Piscina) montados en `js/views/planificacion.js`.
- `js/domain/temporada.js` — **puro** (sin DOM, store, red, i18n ni reloj): normalización de las hojas `Temporadas`, `Fases`, `SemanasPlan` (id determinista `sp-<temporada>-<lunes>`; sólo se guardan las semanas editadas, el resto se genera con `generarSemanas`) y `EventosTemporada`; asignación de fase por fechas, validaciones (`validarPlan`: fases solapadas = error, huecos, fases/eventos fuera de la temporada), clasificación de las líneas del plan por contenido (`volumenPlanSesion`, **único punto** que reparte el volumen de un plan entre contenidos), agregados reales (`agregarPlanes`, `agregarCargas`), `resumenSemanas` (previsto vs real, desviación ±10 %, estado), `totales` por fase, `sugerencias` (contenido acumulado, semanas previas a competición A/B, tapering, semanas sin previsto), herramientas (`ajustarVolumenes`, `desplazarPlan`, `aplicarPlantillaFase`, `copiarPlanSemana`), `eventosDeTemporada` + `FUENTE_CALENDARIO` (registrada con `registrarFuente` en `calendarioService`) y `temporadaDemo`.
- Los volúmenes son metros por nadador y semana. El **real** sale de Cargas (media por nadador) o, si no hay, de los planes de entreno (Entrenamientos + EntrenoLineas, realizados y planificados); se puede forzar el origen. Con `Temporadas.grupoId` sólo cuentan las sesiones y nadadores de ese grupo.
- `js/application/temporadaService.js` — `crearTemporadaService(repo, {ahora, nombreFase})`: repositorio inyectado (store o memoria); CRUD de temporadas (una activa, borrado en cascada), fases (los solapes exigen `forzar`), eventos y semanas, `resumen` (modelo completo de la vista) y herramientas con previsualización.
- `js/views/temporada.js` y `js/views/temporada-grafico.js` — sólo presentan. Gráfico SVG propio (barras apiladas por contenido, línea de previsto, bandas de fase, marcadores A=rombo/B=cuadrado/C=círculo con su letra, foco por teclado y tooltip), línea de tiempo (Gantt) y tabla; en móvil, lista de semanas con mini-barras. Estilos con prefijo `tp-`; textos en `js/locales/temporada.{es,en,it}.js`.

## Plan de entreno detallado y PDF (arquitectura en capas)
- `js/domain/entreno.js` — **puro** (sin DOM, store, fetch ni i18n): números tolerantes (`num`), salidas (`parsearSalida`: ciclo `C/1'10"` y descanso `d/15"`, con forma canónica), cálculo (`distanciaBloque` = series x distancia; `agruparSets` → Dist. Set; `totales` → min y m de la sesión; `resumen`), validación (`validarLinea`, `validarSesion`: series/distancia/tiempo numéricos = error; salida no reconocida, volumen objetivo, duración y diferencia con la carga registrada (`cargaRegistrada`, tolerancia 10 %) = aviso), edición del borrador (`anadirSet/Fila`, `quitar*`, `mover*`, `duplicarSet/Fila`, `renumerar`), `duplicarSesion`, plantillas (`PLANTILLAS`, `lineasDePlantilla`), `planDemo`, `sugerencias` (autocompletar) y nombres de fichero (`Alevin-2026-10-15-jueves.pdf`).
- `js/domain/desglose.js` — **puro**: reparto de cada fila entre varios **contenidos** y **estilos** y sus totales. Decisión: los metros de un componente son `series x metrosPorRep` (4x100 de crol = 400 m de crol; los 100 m son por repetición y se muestran como «m/rep»); el total de la sesión sigue siendo la suma de Dist. Bloque. Un único componente auto recibe toda la distancia; los auto sin metros se reparten a partes iguales el resto; manual (metros o %) siempre gana y al fijarlo los auto con metros se reequilibran en proporción (`fijarReequilibrando`); lo no asignado cuenta como «sin contenido» y pasarse se ajusta proporcionalmente (ambos avisan: `validarReparto`, `asignarResto`). `parsearEjercicio`/`autocompletarLinea` entienden `4x100 Crol. 75 AeL-25 Tope`, `8x50 (25 Sprint+25 AeL)`, `6x100 AeL`, `3x(200 AeM + 100 AeI)` con los alias de `TiposCarga.alias` (`AeL`, `Tope`, `Pn`...). `desgloseSesion(lineas, {tipos})` → `{totalM, porContenido:[{contenido,tipoId,metros,pct}], porEstilo, porSet, filas}` (% con 1 decimal que suman 100; filas antiguas sin componentes van al contenido de su objetivo) y `volumenPorContenido(sesiones)` (lo usa `temporada.volumenPlanSesion`). `textoResumen`/`textoEjercicio` dan «Volumen total: 400 m (AeL 300 m · Sprint 100 m) · Por estilo: Crol 400 m».
- `js/application/entrenoService.js` — `crearEntrenoService(repo, {genId, club})`: repositorio inyectado. `guardarPlan` (sustituye las líneas; los errores impiden guardar, los avisos no), `eliminarSesion` (borra también el plan), `duplicarSesion`, `copiarPlan`, `planDesdeSesion/Plantilla`, `sugerencias`, `desglose`, `registrarCargasDesdePlan` (una carga por contenido y nadador con los metros del plan, sin duplicar), `ficha`/`fichasSemana` (datos para el PDF, con `desglose` y catálogo; admiten un borrador sin guardar).
- `js/infrastructure/pdfEntreno.js` — `generarPdfEntreno(fichas, {t, locale, lib})`: A4 apaisado, cabecera con colores y logo del club (texto claro u oscuro según el contraste), tabla jspdf-autotable con sets separados por línea gruesa, Dist. Set en la última fila de cada set, fila TOTALES, cabeceras repetidas y varias páginas si hace falta (el tamaño de letra baja hasta que cabe en una), pie con club, fecha de generación y página. Los textos salen de `js/locales/entreno.{es,en,it}.js`. La librería se carga de forma diferida (`cargarLibreria`; `usarLibreria` para pruebas). `js/infrastructure/driveEntrenos.js` guarda el PDF en `cnl/entrenos` con `drive.ensureFolderPath/findFile/upload` (si ya existe lo actualiza).

## Cargas y contenidos de entrenamiento (arquitectura en capas)
- `js/domain/cargas.js` — **puro** (sin DOM, store ni i18n): catálogo predefinido (`CATALOGO_PREDEFINIDO`, 10 contenidos con id estable `tc-<clave>`), `normalizarNombre` (sin tildes/mayúsculas/espacios), `validarTipo`, siembra (`sembrarCatalogo`), migración (`migrarHeredados`, `prepararCatalogo`), agregados semanales (`agregarSemana`: media por nadador con carga, por contenido y por día) y evaluación de objetivos (`evaluarObjetivo`, `evaluarSemana`).
- `js/application/cargasService.js` — `crearCargasService(repo, {generarId})`: repositorio inyectado. Crear/editar/activar/mover/borrar/fusionar contenidos, `registrarCarga` (valida nadador, fecha, metros, RPE, minutos, contenido activo y sesión opcional), `semana()`.
- `js/views/cargas-contenidos.js` — gestor "Contenidos de entrenamiento" (usado en Cargas y Configuración) y utilidades de presentación (`chip`, `fmtM`). `js/views/cargas.js`, `inicio.js`, `nadadores.js` y `mi-espacio.js` sólo presentan.
- **Decisiones**: `Cargas.tipo` guarda el NOMBRE del contenido (valor en español, compatible con datos antiguos); la comparación es por nombre normalizado y renombrar un contenido personalizado actualiza sus cargas. Los predefinidos se pueden desactivar/editar (descripción, color, objetivos) pero no borrar ni renombrar; un contenido con cargas no se borra (se desactiva o se fusiona con otro). Las claves de i18n son `tc.<clave>.nombre|desc`; los personalizados se muestran tal cual.
- **Siembra y migración** (`store.ensureCatalog`, al abrir/sincronizar/importar/vaciar): añade los predefinidos que falten (por id, sin duplicar ni pisar ediciones); los tipos antiguos de Cargas/ObjetivosCarga que no coinciden con el catálogo (Aeróbico, Velocidad, Fuerza...) pasan a contenidos personalizados "heredados" con su nombre original (Piernas y Técnica coinciden con los predefinidos); los objetivos de ObjetivosCarga pasan a minSemanalM/maxSemanalM del contenido (sin pisar uno ya definido) y esas filas se eliminan. Las cargas no se reescriben.
- **Criterio de objetivos** (Cargas e Inicio): metros medios por nadador con carga esa semana (o del nadador elegido) frente al objetivo por nadador.

## Individual use (no roles, no sharing)
Whoever signs in is the coach and can do everything. There are no roles, no `Usuarios` sheet, no sharing/joining sheets and no *Mi espacio* view; `auth.role()` and the services' `puedeEditar` option no longer exist. The only read-only state is `store.soloLectura`, set when the club file was written by a newer version of the app. Multi-device use is the same person on several devices: changes are merged per row (see *Concurrencia*). The *Comunicaciones* sheet and the *Avisos y notas* view hold the coach's own notices and notes (they can be copied to be passed on elsewhere); the app never sends them to anyone.

## Shell and PWA (layered)

`js/app.js` only composes. The shell is split into small modules under `js/presentation/shell/`:

| Module | Responsibility |
|---|---|
| `boot.js` | composition: loads the core modules, builds the runtime object `rt`, wires the application services to the real adapters (browser flags, clock, cache cleanup), start flow |
| `shell.js` | `renderShell`, `mostrarVista` (route -> view, title, announcement, focus), footer (Settings only), `refrescarShell` |
| `header.js`, `accountMenu.js` | 56 px header, bell, settings/connection menu (language, theme, Drive status, disconnect / demo actions) |
| `nav.js`, `navModel.js` | one `<nav>` for sidebar and bottom bar, the "More" sheet; the model (groups, bar items, redirects, icons) is pure data |
| `banners.js`, `offline.js` | demo / update / offline / integrity banners with the `.alert` component; `navigator.onLine` |
| `pwaInstall.js` | install prompt, service worker registration, "new version" flow (the user chooses when to reload) |
| `themeApply.js`, `a11y.js`, `marca.js` | club colour per light/dark mode; title / live region / focus / skip link; club name and logo |
| `screens.js`, `conexion.js` | screens before the shell (start, configuration needed, picker, wizard, recovery); adapter for demo mode and "connect Drive" |

Business rules left the shell and live in the application layer, with every concrete dependency injected:

- `js/application/sesionService.js` — `crearSesionService({auth, drive, prefs, CLAVES, store, banderas, limpiarDatosLocales, espera, log})`: `resolveStartMode()` / `decidirArranque()` (drive | demo | start | config | tutorial), `resolverClub()` (-> abrir | crear | elegir | error), `reconectar()`, `cerrarSesion({preguntarPendientes})` (upload with a deadline, ask when it could not, revoke, erase local mirrors; the demo never uploads). Entering and leaving the demo is `application/modoService.js`.
- `js/application/avisosService.js` (+ `domain/avisos.js`) — `crearAvisosService({listar, ahora, visto})`: `contarNoLeidos()` for the bell (notices of the last 7 days written after the last visit) and `marcarVistos()`.

Ports used by the shell services (browser implementations are in `boot.js`):

| Port | Shape | Browser adapter |
|---|---|---|
| `banderas` | `{selectorForzado(), limpiarSelectorForzado(), demoGuardada()}` | `sessionStorage['cnl:elegir']`, `localStorage['cnl:mode']` |
| `visto` | `{leer(), escribir(isoDate)}` | `localStorage['cnl:avisos-visto']` |
| `ahora` | `() => Date` | `new Date()` |
| `limpiarDatosLocales` | `() => Promise` | `cache.js` |
| `espera` | `(ms) => Promise` | `setTimeout` |

**Service worker.** `sw.js` is hand-written except the block between `>>> GENERATED` and `<<< GENERATED`, which `scripts/generate-sw.mjs` writes (`npm run build:sw`): the precache list (index, manifest, `css/**` including `css/views/*.css`, `js/**`, `icons/**`, `vendor/**`; `js/infrastructure/fakeGoogle.js` is excluded on purpose) and a `VERSION` that is a content hash (text normalised to LF, so CRLF and LF checkouts agree). `npm run check` runs `generate-sw.mjs --check`: it fails when the list is stale and when an `import`, a `useStyles('<name>')` stylesheet or an `index.html` reference points to a missing or non-precached file. Strategies: stale-while-revalidate for HTML/JS/CSS, cache-first for `vendor/` and `icons/`; only same-origin GET is handled, so Google/Drive/Identity Services always go to the network. A required file that fails to precache aborts the install (the old worker keeps running); `vendor/*` are optional. There is no `skipWaiting` on install: the page shows "A new version is available - Reload" and sends `SKIP_WAITING` on the user's click, then reloads once the new worker controls it.
